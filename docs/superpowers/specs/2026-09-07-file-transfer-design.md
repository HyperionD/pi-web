# 文件传输与上传限制设计

## 背景

当前工作区文件上传通过 JSON 携带 Base64 内容，受 `1 MiB` 请求体限制；对话附件也通过 JSON 发送。文件树已有安全的原始文件读取接口，但没有下载操作和传输进度反馈。

## 目标

1. 在现有设置中配置工作区上传上限，默认 `100 MiB`。
2. 工作区文件上传改为流式传输，避免 Base64 膨胀和 JSON 请求体限制。
3. 在文件树中增加文件下载操作，并显示上传、下载进度。
4. 对话附件明确显示限制；超出限制时不发送，并提示先上传到工作区。
5. 保持工作区路径校验、允许目录策略、管理员设置保护和现有文件覆盖语义。

## 非目标

- 不实现断点续传、分片上传、并发上传队列或云端对象存储。
- 不改变普通对话文本文件当前 `256 KiB` 内联阈值的语义；只补充可见提示和超限引导。
- 不取消服务器、反向代理、浏览器或磁盘本身的资源限制。

## 配置

沿用现有 `pi-web 应用设置` 和管理员密码保护，在 `workspace` 下增加：

```json
{
  "workspace": {
    "maxUploadBytes": 104857600
  }
}
```

- 默认值：`100 MiB`。
- 最小值：`1 MiB`。
- 保存配置时校验为有限、正整数；超过实现允许的最大安全值时拒绝。实现阶段使用 `2 GiB` 作为最大值，避免整数溢出和异常资源消耗。
- 清除该字段时恢复默认值。
- GET app config 返回生效后的配置；前端设置表单以 MiB 展示，保存时换算为 bytes。
- 上传接口每次读取生效配置，因此保存后无需重启即可生效。

## 工作区上传 API

保留现有 `POST /api/workspaces/{workspaceID}/files/upload` 路径，但新增 `multipart/form-data` 传输格式：

- 表单字段 `path`：工作区相对路径。
- 表单字段 `overwrite`：`true` 或 `false`。
- 文件字段 `file`：待写入内容。

服务端在读取文件流前校验路径和工作区访问权限；使用当前配置的 `maxUploadBytes + 1` 读取上限，超过时返回 `413`。文件先写入同目录临时文件，完成后再根据覆盖语义原子替换；失败时清理临时文件。成功响应继续返回 `FileContent`，以保持前端刷新和打开文件的行为。

为兼容已有客户端，短期内可继续接受旧 JSON/Base64 格式，但新前端必须使用 multipart；旧格式同样受配置上限约束，不再使用固定 `1 MiB` 上限。

## 工作区下载

复用现有 `GET /api/workspaces/{workspaceID}/files/raw?path=...`，保留 `SafeJoin`、真实路径边界检查、目录拒绝和 `ServeContent` 的 `Content-Length`。

文件树文件操作菜单新增“下载”。前端使用 XHR 请求 Blob：

- `onprogress` 更新已下载字节、总字节和百分比；未知总大小时显示已处理字节。
- 完成后通过 object URL 触发浏览器下载，随后释放 URL。
- HTTP 错误显示服务端错误信息，不产生空下载文件。

## 进度反馈

新增统一的文件传输状态区域（沿用现有临时错误/状态反馈样式）：

- 上传：`正在上传 filename · 12.4 / 100 MiB · 12%`。
- 下载：`正在下载 filename · 12.4 / 100 MiB · 12%`。
- 完成后显示短暂成功状态；失败时显示明确错误。
- 同一文件树操作期间禁用重复触发，避免同一路径并发覆盖。
- 不要求取消按钮；页面离开或请求失败时清理状态和临时 object URL。

## 对话附件提示

附件区增加固定说明，提示：

- 普通文件超过 `256 KiB` 不会内联到 prompt。
- 对话请求整体仍受 JSON 请求体限制，图片和多个附件会共同占用额度。
- 超过可发送范围时提示：`对话附件超过大小限制，请先上传到工作区。`

文件选择逻辑在读取前检查可判定的文件大小：

- 普通文件超过 `256 KiB`：不伪装成可用内容，展示超限状态和工作区上传提示。
- 图片或组合附件可能触发请求体限制时：阻止加入发送队列，并显示工作区引导。
- 对话附件区域显示当前工作区上传上限，避免用户不知道可替代路径。

工作区上传入口仍由文件树菜单提供；本次不自动把对话附件复制到工作区，以避免隐式写入和路径选择歧义。

## 错误处理与安全

- 所有工作区文件操作继续经过 workspace access middleware 和允许目录策略。
- 上传路径在创建临时文件前通过 `SafeJoin` 校验；临时文件权限为 `0600`。
- `413` 错误包含可读的大小限制信息，前端转换成中文提示。
- 不把管理员密码或完整本地路径暴露给前端错误提示。
- 下载继续设置 MIME 和 `X-Content-Type-Options: nosniff`。

## 测试要求

### Go

- app config 默认值、MiB/bytes 校验、最小值/最大值、清除恢复默认值。
- multipart 上传成功、覆盖、路径越界、超过配置上限、临时文件清理和旧 JSON 兼容行为。
- 下载现有安全检查和 Content-Length 行为不回归。
- API 超限返回 `413`，错误消息包含配置限制。

### 前端

- API 层上传使用 multipart，保留 overwrite/path 字段；下载 Blob URL 清理。
- 文件树上传和下载分别转发 progress 事件、完成/失败状态。
- 设置表单正确加载、显示和保存 `maxUploadBytes`。
- 对话附件对普通文件和图片的超限提示；提示包含“上传到工作区”。
- 进度文案使用安全文本节点，不把文件名当 HTML。

## 验收标准

- 设置中修改上传上限后，新的工作区上传无需重启即可使用新值。
- 在限制内的大文件可稳定上传，不再因为 Base64/JSON 的 `1 MiB` 固定限制失败。
- 文件树可下载任意已授权的普通文件，并实时显示进度。
- 上传和下载失败均有可读反馈，不留下半文件或临时 object URL。
- 对话附件超限时不会提交请求，并明确指导用户先上传到工作区。
