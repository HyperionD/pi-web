# 离线模型设置简化设计

## 目标与边界

服务器侧以 Pi 的 `--no-extensions --list-models` 返回值作为统一可选模型目录，包含 Pi 已配置且可用的 `openai` 等内建提供商及可选 `models.json` 中的自定义模型；所有账号只能从该目录选择自己的默认模型。一个账号的偏好跨工作区生效，不改变其他账号。保留当前会话临时切换模型的能力。Web 不编辑连接地址、模型定义或凭据，也不把这些信息写入 SQLite。

简化 Web 设置的日常入口，不删除 Pi 原有 `settings.json`、pi-web 应用配置、账号权限或会话记录。项目级非模型行为设置仍可由管理员在高级入口管理。

## 当前实现与问题

- `SettingsDialog.astro` 混合了全局/项目/个人范围、Pi 行为、应用设置、API key/OAuth 和模型选择。
- `settings.go` 将全局、项目文件和个人全局/项目 SQLite 模型偏好依次覆盖；项目偏好会压过账号全局偏好。
- `/api/workspaces/{id}/models` 调用 `pi --no-extensions --list-models`，可返回 Pi 已配置的内建与自定义模型；出错时原实现可能返回伪造的回退模型。
- 保存个人偏好和 `/api/sessions/{id}/model` 尚未根据 Pi 当前可用模型列表校验。运行时启动、压缩和重建使用个人有效模型；状态叠加可能掩盖会话临时切换后的真实模型。

## 数据与规则

1. **目录**：服务端直接使用 Pi `--no-extensions --list-models` 返回的可用模型列表，不解析 `models.json` 来过滤候选。可选的 `models.json` 自定义配置路径为 `~/.pi/agent/models.json`（`PI_CODING_AGENT_DIR` 设置后使用该目录）；无该文件仍允许已配置的 `openai` 等内建模型。对 Web 只返回 Pi 列表元数据及无密钥的诊断信息，不返回 `baseUrl`、`apiKey` 或原文件内容。按 provider ID + model ID 组成唯一标识，稳定排序。
2. **不可用**：`models.json` 缺失不是错误；Pi 模型列表为空或命令失败时返回可解释错误和空目录，不以默认厂商/模型冒充可用模型。若自定义配置有误导致 Pi 命令失败，沿 Pi 错误路径提示。现有 mock 模式可继续使用确定性测试模型，但不得与真实目录规则混用。
3. **账号偏好**：复用 SQLite `user_model_settings` 的 `global` 记录，保存 `defaultProvider`、`defaultModel`、`defaultThinkingLevel`。保存时模型必须成对提交并在目录中；仅调整思考级别也须校验枚举。设置页的“恢复管理员默认”清除账号模型选择。后台不再接受新的个人项目级模型写入；旧项目级记录保留供回滚，不再参与有效模型计算。
4. **默认与继承**：优先采用账号全局选择；否则采用 `~/.pi/agent/settings.json` 的全局默认 provider/model（仅当两者成对且在目录中）；再否则使用目录稳定排序的第一个模型。工作区 `.pi/settings.json` 中的模型字段及旧个人项目偏好不影响选择；其他非模型字段仍遵循现有全局→项目覆盖。Pi 列表不再包含已选模型时，不删除旧偏好数据，但新会话与显示结果按上述默认规则回退，并在设置页提示选择已失效。若 Pi 无可用模型，则禁用保存、切换和新运行时初始化并明确报错。
5. **会话**：新会话或运行时初始化时使用该会话所有者的有效默认模型；用户在会话中临时切换只改变该会话的运行时/会话事件，不改账号偏好。后续恢复/压缩遵循已有会话模型事件优先于账号默认的规则；如当前代码未做到，实施时需修正而非覆盖会话选择。Pi 列表不再包含某个历史模型后，旧会话可显示其历史信息，但再次使用该模型之前必须校验当前可用列表并给出可恢复错误。

## 接口与权限

- 保持现有工作区模型列表和设置接口形状兼容；模型列表返回 Pi 当前可用目录（错误保留显式状态）。设置响应中 `effective` 的模型字段反映账号级有效选择，同时为 UI 增加必要的“偏好失效/使用默认”状态，不暴露凭据。
- 账号可通过现有 `PUT /api/workspaces/{id}/settings` 的 `personal` + `global` 更新自己的默认选择；禁止 `personal` + `project` 的新模型写入。管理员仍可修改共享非模型设置，但通过 `global`/`project` 请求写入模型字段时显式拒绝，避免误以为修改了统一目录。
- `POST /api/sessions/{id}/model` 在现有会话访问与归属校验后检查 Pi 当前可用模型成员资格；纯思考级别变更也须有可用模型。请求越权、无效 provider/model、Pi 列表不可用均显式失败。校验由服务端完成，不能依赖 UI 下拉框。
- 权限仍按工作区授权和会话所有权执行；admin 查看历史会话的规则不随此次设置简化而扩大。

## 界面与操作

- 常用设置区：账号“我的默认模型”下拉框（provider/model 组合）、思考级别、继承/恢复管理员默认；只列出 Pi 当前可用模型，没有“custom…”和全局/项目/个人范围选择。保存只更新账号偏好；另设“应用到当前会话”操作，且不暗中改变其它已运行会话。
- 管理员的高级区：保留应用配置（品牌、上传限制、允许目录）及 Pi 的非模型行为设置；展示 Pi 可用模型数/错误及可选的自定义模型配置路径，只读且不回显秘密。现有 API key/OAuth 管理仅保留在管理员高级区，且不回显秘密。
- 普通账号不显示应用配置或凭据编辑控件。无工作区、Pi 模型列表不可用、偏好失效、保存失败均展示明确状态并禁用不安全操作；保留键盘焦点和可访问标签。

## 迁移、测试与交付

- 不修改或清理用户现有 `.pi/settings.json`、全局 `settings.json` 和 SQLite 旧记录；停止项目级模型覆盖之前，在变更说明中告知旧偏好会被忽略，用户可重新选择账号级模型。保留非模型设置 API 的兼容性。部署无需新增依赖或在线资源。
- 后端单测：Pi 列表包含内建与自定义模型（`models.json` 缺失亦可用）、列表为空/命令失败、不泄露秘密、偏好继承及失效回退、账号隔离、项目覆盖忽略、越权和未列入目录的模型拒绝、会话恢复/临时切换。mock 测试明确区分真实模式。
- 前端单测：下拉框仅列 Pi 可用模型、偏好跨工作区、Pi 列表失败和失效提示、管理员/普通账号可见性、恢复默认、保存及当前会话切换失败。验收：Pi 列表返回的候选全部显示，含已配置的 `openai`，且未返回的模型不能保存，两个账号在同一工作区选择不同默认模型，重启和跨工作区保持各自选择，临时切换不改默认。
- 运行 `bun run lint`、`bun run typecheck`、`bun run test`、`bun run backend:test`、`bun run build:single` 和 `bun run check:embedded-assets`；前端产物同步到 `static/`，检查 diff 和工作区状态，不包含 `public/file-viewer/` 等无关文件。
